# Automated acceptance evidence

The automated matrix uses public Solidity interfaces/events/token outcomes, order-module exports, storage-adapter operations, browser/wallet/RPC/HTTP flows, and documented startup/build/ABI commands. It does not replace the manual extension/mobile-wallet checks or Yves's release approval.

Run `pnpm install --frozen-lockfile`, `pnpm run check`, then `pnpm run test:e2e` as described in [README](../README.md); Playwright starts, prepares, and stops its own disposable Anvil. Installed Chrome can be selected with `PLAYWRIGHT_CHANNEL=chrome`. Transaction-writing suites run serially against Anvil; independent browser contexts represent different parties. The production build smoke uses a synthetic address and is not deployable release configuration.

Wallet fixtures implement the public EIP-1193 interface and submit real transactions to Anvil. Controlled HTTP/RPC responses exercise failures; these tests do not claim that an actual browser extension or WalletConnect mobile wallet was manually validated. Synthetic signed orders may appear in local test artifacts. No real user trade data or credentials belong in artifacts.

The remaining manual matrix must record the exact browser, extension wallet, mobile OS/wallet, WalletConnect configuration, origin and candidate revision. It includes creation, approval, signing, sharing, acceptance, cancellation, rejected/pending actions, responsive layout and browser-storage behavior. Public deployment remains gated on that evidence and Yves's approval.

The integrated browser run uses Chrome 152.0.7977.84 on macOS with Playwright 1.63.0, a 320 × 740 maker viewport and a 1280 × 900 independent taker viewport. It saves mobile maker/history/large-amount and desktop taker screenshots under `web/test-results/`. The large-amount regression first measured a 742px document at a 320px viewport; wrapping now preserves exact digits within the page. Successful and invalid signed fragments are checked against outgoing requests and browser diagnostics; all five explicit transaction submissions in the complete journey target only the configured local RPC.
